- 医疗导诊场景需求分析

  ​		用户问题类型多样，包括流程类问题、症状描述类问题以及规则说明类问题，不同类型对系统能力要求不同。其次，用户表达高度口语化且非结构化，往往缺乏标准医学术语，需要较强的语义理解能力。再次，导诊过程通常是多轮交互，系统需要根据用户补充信息动态调整判断，因此必须具备状态管理与流程控制能力。此外，医疗场景对回答准确性和可控性要求较高，不能依赖纯生成式回答，必须基于知识库进行检索并保证可追溯性。综合来看，系统不仅要具备语义理解能力，还要支持知识更新、流程控制和工程化部署，才能满足真实导诊场景的需求。

  七、测试与评估方式（3分钟）

  - 假设 query：

    > “右下腹持续疼痛挂什么科”

    gold_rule_id = 101

    RAG 返回 8 个 chunk，对应的 rule_id = [101, 110, 120, 101, 130, 140, 101, 150]

    - 命中 chunk：101_1、101_2、101_3
    - **Recall** → 至少召回 1 条 → 成功
    - **Precision** → 3/8 = 0.375
    - MMR -- 1 / 0.5 / 0.33

  

  输出结果
  意图准确率: 85.00%
  答案正确率: 78.00%
  答案相关率: 92.00%
  答案完整率: 75.00%

  整体通过率: 80.00%

  总结
  | **指标**       | **判断方式**                                  |
  | -------------- | --------------------------------------------- |
  | **答案正确性** | 答案是否包含期望关键词（evaluation_criteria） |
  | 答案相关性     | 答案是否回应了问题（问题与答案的词汇重叠）    |
  | 答案完整性     | 答案是否包含该类型应有的要素（如科室+建议）   |

  - 四维评测体系：意图识别 / RAG检索 / 端到端 / 性能

  - 评测指标：准确率 / MRR / Recall@K / P50/P95/P99延迟

  - **P50**：50% 的请求延迟在这个时间以下，也就是中位数响应时间

    **P95**：95% 的请求延迟在这个时间以下，衡量绝大多数请求的响应性能

    **P99**：99% 的请求延迟在这个时间以下，衡量系统在极端情况下的响应性能

    目标：P95 < 3秒（用户可接受范围）
    底线：P99 < 5秒（极端情况不超时）

  - 达标标准：意图≥85% / MRR≥70% / 端到端≥80% / 错误率≤1%

 优化方法总结
一、数据处理优化

| 优化点       | 方法                       | 效果                      |
| ------------ | -------------------------- | ------------------------- |
| 方言转写     | Whisper + LLM改写          | 消除歧义，提升分类准确率  |
| 文档解析     | Docling/PyMuPDF/pdfplumber | PDF/Word/Txt → 结构化JSON |
| 文本清洗     | 正则+去噪+归一化           | 提升数据质量              |
| 样本平衡     | 欠采样/SMOTE/class_weight  | 解决类别不均衡            |
| 错误数据重标 | 找出错误样本 → 重新标注    | 直接提升准确率            |
| 样本分类     | 分成10个大类，再区分186类  | 直接提升准确率            |
