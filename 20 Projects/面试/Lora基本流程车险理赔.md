# 第八阶段：LORA如何优化

针对你提供的车险理赔 LoRA 微调项目，我把测试、数据准备、向量库建立、检索机制、优化方案整理如下：

------

### 1. 准确率测试方法

- **指标选择**：
  - **Precision**（精确率）= 真正例 / (真正例 + 假正例)，衡量预测正例的可靠性。
  - **Recall**（召回率）= 真正例 / (真正例 + 假负例)，衡量模型覆盖能力。
  - **F1-score** = 2 × (Precision × Recall) / (Precision + Recall)，综合精度与召回率。
- **测试流程**：
  1. 构建标准化测试集，覆盖全部 183 类车险标签，每类保证一定样本数。
  2. 对事故文本或条款数据进行预测。
  3. 对比模型输出与人工标注，计算各类指标。
  4. 对关键场景或罕见类别进行单独分析，发现模型弱点。

------

### 2. 数据准备

- **文本数据**：

  - 清洗：去除噪声字符、冗余信息、格式统一。
  - 标签规范化：统一事故类型、条款编号等标准格式。
  - 类别均衡：对少数类进行过采样或生成增强样本。

- **语音数据**：

  - 转写成文本（ASR），统一格式后再标注标签。
  - 可考虑音频向量化（如 Wav2Vec2）用于语义检索或多模态训练。

- **图片数据**：

  - OCR 提取文字信息，结构化存储。
  - 关键图片特征可用 CLIP、BLIP2 等模型提取向量。

- **视频数据**：

  - 关键帧抽取 + OCR 或图像特征提取。
  - 视频语音可先转文本，再统一处理。

- **clean 数据示例**：

  ```
  {
    "id": "case_0001",
    "text": "2026-01-15，车辆刮擦，责任方乙方，损失金额3000元",
    "labels": ["刮擦", "第三方责任", "小额赔付"],
    "metadata": {"source": "理赔系统", "format_version": 1}
  }
  ```

  每条数据必须包含 **文本内容、标签、来源信息**，保证统一格式和标注准确。

------

### 3. 向量库建立

- **文本向量**：
  - 使用 Qwen3-8B 或其他 embedding 模型生成文本向量。
  - 可存入 Milvus、FAISS、Weaviate 等向量数据库。
- **多模态向量**：
  - 图片、视频向量统一存储，支持跨模态检索。
- **索引策略**：
  - 支持高维向量的 IVF+PQ、HNSW 索引，保证检索效率。
  - 可以按事故类型、时间、标签分片，提高查询速度。

------

### 4. 检索机制与优化（参考 LawLora 项目）

- **基础机制**：
  - Qwen3-8B 生成 query embedding。
  - Milvus/FAISS 建立向量索引。
  - 检索 top-K 相似案例或条款文本。
- **优化方法**：
  - 微调 embedding 模型，使同类案件聚类更紧密。
  - 使用 hybrid 检索：向量 + 关键词过滤，提高精度。
  - 对少数类或新类型案件使用扩展 prompt 或增量训练。
  - 检索结果可以加 reranking 模型，提高最终匹配质量。

------

### 5. 准确率不高的优化方法

- **数据层**：
  - 增强少数类样本或生成 synthetic 数据。
  - 提高标注一致性，排查标注错误。
- **模型层**：
  - 调整 LoRA rank 或训练轮数。
  - 增加 domain-specific instruction 数据。
- **检索层**：
  - 调整向量索引参数（ef、nprobe）。
  - 加入 reranking 或二次检索机制。
- **评估层**：
  - 对低 F1 的类别单独分析，针对性微调。

------

**完整流程图**：从语音/文本/图片/视频数据 → 清洗 → 向量化 → 检索 → LoRA 推理 → 分类评估 → 输出结果，直观展示整个系统端到端流程。
