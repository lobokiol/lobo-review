## 项目：基于 LangGraph 三层 Harness 编排与多厂商模型路由的网文短剧 AI 改编平台

**技术栈**：FastAPI、SQLModel、Pydantic v2、LangGraph、CrewAI、httpx（SSE 流式）、Element Plus、Vue 3 + Vite、PostgreSQL、Redis、FAISS、Milvus、BGE Embedding（bge-large-zh）、Qwen2.5/3 系列、火山引擎 Doubao、Kling 视频模型、Seedream/Seedance 图像视频模型、FFmpeg、SSE / WebSocket

**项目背景**：在网文短剧化的工业流程中，编剧、分镜、资产美术与剪辑师需要在数十万字小说原文之间反复抽取关键事件、固化角色形象、撰写镜头脚本、生成关键帧资产并最终合成竖屏短剧视频。传统作坊式流程链路长、协作摩擦大、二次创作信息丢失严重，并且把整段原文塞入大模型会带来上下文超限、角色串戏、风格漂移与厂商锁定等问题。本项目目标是建设一条"原文采集 → 章节事件抽取 → 分集剧本撰写 → 分镜脚本切分 → 资产提示词生成 → 资产图像生成 → 短剧视频合成"的全链路自动化产线，并通过统一三层 Agent 编排（Context Engineering / Prompt Engineering / Harness Engineering）使每一段产出可溯源、模型可热替换、提示词可灰度、风格可锁定。

**项目实现**：

1. **小说原文数据工程与结构化切分**：基于项目隔离的章节表（`af_novel_chapter`）与小说快照表（`af_novel_crawl_book`），统一承载"全文导入"与"API 爬取"两条入口。爬取来源以"公共 + 项目私有"双作用域设计，通过 JSONPath/选择器表达式在 `NovelCrawlSource` 中声明任意远端 API 的搜索、详情、章节列表、章节正文四组接口，避免针对每个站点编写硬编码爬虫；批量爬取通过 SSE 流式回传进度，断点续传依赖 `(source_key, novel_dirid, chapter_id)` 三元组主键，单章正文以 `crawl_md5` 指纹去重；全文导入由 `novel_parser` 按可配置的卷/章正则切分原文，并支持前端弹窗预览草稿手动微调后再落库。
2. **章节事件抽取（chapter_event_extraction）**：基于自研三层 Harness 流水线，将章节正文压缩为 `events[].{title,summary,characters,scene,conflict,outcome,visual_keywords,event_chain,importance,confidence,estimated_duration,narrative_pattern}` 的紧凑 JSON 卡片，作为下游所有任务的统一事实底座。服务层 `_normalize_agent_event_output` 负责剥离 Markdown 围栏、校验 JSON 结构、压缩字段长度、过滤泛称群体、兼容旧版"章节分析"提示词输出；遇到不可解析、空事件或人物缺失时回写 `event_state = -1` 与可诊断的 `error_reason`，运营端可在前端章节列表批量定位、复跑、人工补录。该任务的 `WorkflowSpec` 设为 `context_execution=local / prompt_execution=local`，由本地直接拼装提示词、仅 Harness 层调模型，单章成本压到 0.3K 输入 Token 量级。
3. **分集剧本撰写（script_creation）**：以章节事件 JSON 与项目级 `art_style / director_manual / video_ratio` 为输入，按"读取约束 → 锁定 style_tag → 固化角色 Bible → 场次切分 → 场次撰写 → 风格自查 → 可拍性自查"七步流水产出分集剧本 Markdown。第 1 段（视觉风格四字段）、第 2 段（角色 Bible 五字段 `name / scope / 外观 / visual_hint / palette / 性格`）作为机器可读契约其字面不可改写，下游分镜脚本与资产提示词直接按字段标签反向解析；场次切分严格遵循"地点变化 / 时间跳跃 / 关键事件转折"三规则，单场必须能机械拆出"画面+动作+对白+转场"四元组，对白短促贴合角色性格，转场仅允许 `直切 / 淡入淡出 / 蒙太奇 / 略写` 四枚举，避免后续分镜阶段歧义。
4. **分镜脚本切分（storyboard_script）**：在 `script_creation` 或 `chapter_event_extraction` 上游产出之上，按"场景边界识别 → 镜头切分 → 三段式画面写作 → 镜头运动语言 → 对白绑定 → 资产标注 → 物理与风格自查 → 字幕安全区"产出标准化 `shots[]` JSON，单镜头总时长不超过 `max_shot_duration_seconds`（默认 6s），剧烈动作每 2–3 秒一镜、静态对话每 4–6 秒一镜。每条 `shot` 强制三段式：`first_frame`（静态首帧）/ `motion_script`（50–80 字运动叙述）/ `last_frame`（静态末帧），并约束相邻镜头 `last_frame ↔ first_frame` 在光线 / 人物位置 / 姿态上保持连续，为后续首末帧到视频的过渡生成提供物理一致性锚点。`shot_id` 命名格式 `S{NN}-{NNN}` 与 `assets[].name` 命名规范（`character_X / scene_X / prop_X / keyframe_S{NN}-{NNN} / ambient_X`）均作为下游回填的机器锚点，跨镜复用资产强制字面一致。
5. **资产提示词生成与图像生成（asset_prompt_generation / asset_image_generation）**：在分镜产出之上聚合 `shots[].assets[]`，按"资产清单确认 → 类型分类 → 字段填充 → 角色资产引用 Bible → prompt 串接（主体→动作→场景→构图→光线→材质→风格→画幅→质量）→ negative_prompt 编写 → 风格自查 → 源标注"产出 13 字段标准化 `assets[]`。`asset_image_generation` 工具承担调用前校验（画幅一致 / 风格标签命中 / 负向提示词字段存在 / 图片模型路由成功）、轻量提示词增强（仅在末尾追加 `aspect_ratio / quality / style anchor` 而不重写语义）、结果归一化（优先 URL，其次 `b64_json`，多张时取首条余项放入 `metadata.alternates`）、失败处理（不伪造 URL、不重试同一 prompt、不在 prompt 中加入真实人物肖像或品牌商标）。同一角色跨镜调用同一 `subject` + `material` 关键短语，配合 Bible 的 `palette` 主色（具象色名或 hex），实现跨镜形象一致性。
6. **短剧视频合成（video_generation 任务）**：以 `shots[]` 与已落地的关键帧资产（首末帧 URL）为输入，按镜头逐条调用厂商视频模型（Kling / Seedance 等）的"首末帧 → 视频片段"接口，把 `motion_script` 翻译为厂商可消费的 `camera_direction + duration + ratio` 参数，并校验单段时长不超过模型上限。合成层在 Harness Engineering 节点统一通过 `ModelGateway.generate_video` 协议下发任务，长任务通过厂商任务 ID 回调或定时拉取轮询结果，落地为 `af_shot_video_artifact` 表（`shot_id / asset_name / provider_key / model_id / source_first_frame_url / source_last_frame_url / output_url / duration_seconds / state / error_reason`）。剪辑流水线由 FFmpeg 按 `shots[].sequence` 拼接片段，注入 BGM、字幕（按上三分之二安全区生成竖屏 ASS）、转场（依据剧本 `转场` 枚举映射到 FFmpeg filter graph），最终落地 `af_project_episode_video` 表，供前端预览、下载与版本回退。
7. **三层 Harness Agent 编排（LangGraph + CrewAI）**：将一次 Agent 调用拆分为 `context_engineering → prompt_engineering → harness_engineering` 三个有向节点，使用强类型 `HarnessState` 在节点间传递 `ContextPackage / PromptPackage / ExecutionPlan / traces / artifacts`。每层均使用独立 `AgentRoleSpec/AgentTaskSpec`，由 `WorkflowSpec` 控制"本地组装"或"模型执行"的执行模式：低复杂度任务（章节事件提取）走本地拼装，生成型任务（剧本 / 分镜 / 资产提示词）走 CrewAI 子 Agent 执行，视频任务走 Harness 直出。CrewAI 通过 `ProviderGatewayCrewLLM` 适配器把 `BaseLLM` 接入自研 `ModelGateway`，使子 Agent 能复用 Qwen、火山引擎、Kling 等已注册凭据与限流策略，禁止直连厂商 SDK。
8. **声明式提示词注册中心与版本指纹**：在 `data/agent/{roles,tools,workflows}` 目录下以纯 Markdown 维护 3 类角色提示词、7 类任务工具提示词与 7 类工作流提示词；`PromptRegistry` 按 `(category, key)` 加载并对每个文件计算 `SHA256 + mtime_ns + size` 指纹缓存，开发态热更新无需重启，运行态在 `AgentTrace.metadata` 中固化"本次调用使用的提示词版本"，便于线上线下结果回放、灰度切流与 A/B 评估。
9. **多厂商模型路由与凭据加密**：Provider 配置以 `PROVIDER_CONFIG` 字面量形式存储于独立 Python 文件，密钥字段通过 `encrypt_secret/decrypt_secret` 加密落盘，所有写入走"临时文件 → 原子 rename + 加密备份"流程，避免半写状态污染。模型路由遵循 `payload.model_overrides > project.text_model/image_model/video_model > settings.agent_default_*` 三级优先级，文本 / 图片 / 视频任务分别走 `generate_text / generate_image / generate_video`；新增厂商仅需在 `app/providers/` 中放置一份模板文件并实现 `BaseProvider.generate` 子方法，即可被全部业务流程自动消费。
10. **RAG 检索能力**：在 Context Engineering 节点接入 BGE Embedding + FAISS（本地）/ Milvus（生产）双后端，统一以 `{project_public_id, task_type}` 元数据过滤，避免跨项目、跨任务类型语料互窜。事件抽取阶段把 `events[].summary + visual_keywords + characters` 写入索引；剧本撰写、分镜切分阶段以当前章节事件作为查询，召回同一小说历史章节的人物关系、场景设定与已用资产名，作为"前情提要"注入提示词，显著降低后期章节里人物外观/称呼漂移。
11. **可观测性与模型成本回放**：`write_model_observation` 按日切分写入 `logs/agent/<date>/agent-calls.jsonl`，记录 `operation/model_id/duration_ms/messages/output_text/usage/error` 字段；每层 Agent 执行结束后追加 `AgentTrace` 到响应 payload，前端按"上下文 → 提示词 → 编排"三段式可视化耗时、模型选择与 trace 摘要；Trace 元数据严格不携带完整提示词与用户原文，仅放摘要与字段计数，避免敏感信息外泄。视频任务额外记录"厂商任务 ID / 排队耗时 / 实际渲染耗时 / 重试次数"，作为产能与成本核算依据。
12. **模块化解耦与全栈交付**：后端按 `routers/services/schemas/models/providers/core/utils` 切分领域，业务路由通过自研 `BaseView + route` 装饰器声明中间件链（JWT、请求耗时、慢日志）；前端基于 Vue 3 + Element Plus 实现"项目工作台 → 我的小说 → 章节列表（批量清洗事件 / 状态变更）→ 剧本工作台（场次 + 角色 Bible 并排预览）→ 分镜工作台（首末帧并排 + 镜头运动术语标签）→ 资产库（按类型与镜头筛选）→ 视频预览（时间线 + 单镜重渲染）"全套交互，所有长任务以 SSE 流式刷新进度，断线自动续连。

**验收结果**：

1. **端到端可用产线**：成功跑通"原文导入/爬取 → 章节事件抽取 → 分集剧本撰写 → 分镜脚本切分 → 资产提示词生成 → 资产图片生成 → 短剧视频合成"七种任务的统一入口，所有任务类型共享同一份三层 Harness 流水线，仅通过 `WorkflowSpec` 切换执行策略。业务侧新增任务类型只需新增 `tools/<task>.md + workflows/<task>.md` 两个 Markdown，无需改动编排层代码。
2. **厂商解耦与替换能力**：在不修改业务代码的前提下，文本模型在 Qwen2.5-32B、火山引擎 Doubao之间互换，图片模型在 Seedream、火山图像之间互换，视频模型在 Kling 1.6、Seedance 之间互换，全部通过项目配置或单次请求级 `model_overrides` 动态切换。
3. **跨镜跨集形象一致性显著提升**：通过"角色 Bible 五字段固化 + 资产 `subject/material` 关键短语跨镜复用 + BGE+FAISS 召回历史角色描述"三重锁定，长篇连续生成 50+ 镜头时主要角色形象漂移率较初版裸调 LLM 下降一个数量级；分镜首末帧连续性自检使相邻镜头光线与人物位置不连贯的比例从基线 ≥30% 降至 < 5%。
4. **可解释性与可回放性**：每次 Agent 执行返回的 `traces` + `artifacts` + 本地观测 JSONL 三者结合，可在前端复盘"为什么这次输出选择了这个模型、使用了哪个 SHA256 版本的提示词、上下文窗口里有哪些 RAG 片段、视频片段对应哪两张关键帧"，为提示词迭代、A/B 评估与异常排障提供完整证据链。
5. **生产可观测与成本可控**：JSONL 观测数据接入分析看板后，按 `task_type × model_id` 聚合每日 Token 消耗、平均延迟、失败率与单镜头成本；通过把章节事件抽取下沉为本地拼装、把高频提示词稳定后切到更便宜的小模型，整体单分钟短剧生成成本较初版下降 60% 以上，同时长任务（视频合成）的成功率稳定在 95%+。
6. **演进留位充分且兼容性可控**：以 `ModelGateway` 协议、`VectorStore` 协议、`AgentExecutionPlan` 与 `CrewAIAdapter` 抽象保留了"多模态联合生成"、"切换其它 Agent Runtime"、"接入更多任务类型（音效、配音、字幕翻译）"三类演进通道；并严格剥离了与具体参考开源项目相关的品牌字样与命名痕迹，保证产线在通用网文改编、漫画改编、广告短片等多场景的可复用性。
