## 一、岗位定位

负责将「图纸审核」真实业务拆解为可落地的智能体系统：**规则比对为主、大模型补盲、人工最终拍板**。不仅做模型调优，更要对**工具设计、评测体系、生产稳定性**负责。

顶尖智能体工程师 = **扎实后端能力** + **大模型产品思维** + **系统架构理解**。

---

## 二、四个核心考察维度

> 承接两个智能体项目的负责人总结：**前两点决定能否做出智能体，后两点决定能否打造可用、稳定、可迭代的系统。**

### 维度一：架构与任务拆解（最关键）

**考察什么：** 能否判断业务问题适配的方案（普通大模型调用、工作流、多智能体等），将真实业务拆分为状态、步骤、失败恢复、工具调用及验收条件。

| 要求 | 本项目体现 |
| :--- | :--- |
| 方案选型克制 | 规则引擎 + 单 Agent + 工具链，非多 Agent 堆叠 |
| 状态机清晰 | 待解析 → 比对中 → 待人工 → 已放行/已退回 |
| 失败恢复 | 工具超时重试、LLM 失败降级转人工全审 |
| 验收可量化 | 标红召回率、误报率、单均审核时长 |

**面试题示例：**

> 图纸审核旺季 20% 退货，你会用普通调用、工作流还是多智能体？步骤怎么拆？

**加分信号：** 能画出「解析→比对→标红→人工」流水线；强调落地系统清晰可组合。  
**减分信号：** 不问业务就上多 Agent；说不出失败怎么办。

---

### 维度二：工具调用与工程

**考察什么：** 工具 Schema 设计、函数调用、权限约束、超时异常处理、上下文压缩。智能体区别于普通调用的核心是**多计划、保状态、跑多步**。

| 要求 | 本项目体现 |
| :--- | :--- |
| Tool Schema 设计 | `extract_order_params`、`parse_drawing`、`compare_params` |
| 结构化返回 | 不符合项含字段、定位、置信度，非纯自然语言 |
| 权限约束 | 工具只读图纸/订单，禁止未授权写库或外发 |
| 上下文压缩 | 长图纸摘要、按检查项裁剪，避免 token 爆掉 |
| 幂等与重试 | 同一订单重复审核不产生脏数据 |

**面试题示例：**

> 设计 `compare_drawing_with_order` 工具，schema 怎么定？模型经常填错参数怎么办？

**加分信号：** 知晓多数引擎失败源于工具设计差、上下文过载、状态无法恢复。  
**减分信号：** 万能函数、整份 PDF 塞 context、不考虑幂等。

---

### 维度三：评测与可观测性（常被低估）

**考察什么：** 有无衡量智能体输出的标准；能否记录、回放、调试 LLM 推理、工具调用及护栏环节。

| 要求 | 本项目体现 |
| :--- | :--- |
| 金标数据集 | ≥200 单，含正常单、退货单、边界单 |
| 指标体系 | 提取准确率、标红召回率、误报率、人工改判率 |
| 全链路 Trace | 按 order_id 回放每步 LLM 输入输出与工具调用 |
| 回归评测 | Prompt/规则变更后跑批对比，防退化 |
| 护栏可观测 | 记录拦截原因，非黑盒 |

**面试题示例：**

> 上线一周退货率只从 20% 降到 15%，你怎么排查？

**加分信号：** 分层定位（解析/比对/LLM/人工），有 golden set 回归思路。  
**减分信号：** 「多调调 Prompt」；无日志、无评测集。

---

### 维度四：生产落地与人机协同

**考察什么：** 状态持久化、断点恢复、人工审核边界、成本延迟控制、误操作防护、日志监控降级回滚、安全护栏。

| 要求 | 本项目体现 |
| :--- | :--- |
| 人机边界 | 智能体标红，**100% 放行须经 2 名审核员拍板** |
| 断点恢复 | 长跑任务中断后从最近成功步骤续跑 |
| 成本延迟 | 规则优先，仅不确定项调 LLM；2卡/4卡按峰值配置 |
| 降级策略 | LLM 不可用 → 全量转人工，宁可多审不可漏放 |
| 安全护栏 | 输入脱敏、输出校验、敏感操作二次确认 |

**面试题示例：**

> 旺季订单暴增 10 倍、API 延迟翻倍，怎么保证审核不堵死？

**加分信号：** 队列优先级、按需调模型、超时降级、审核台只展示标红。  
**减分信号：** 只谈模型能力，不谈 SLA、成本、护栏。

## 三、岗位职责（本项目）

### 3.1 算法 / AI 工程师

| 职责模块 | 具体工作 |
| :--- | :--- |
| **模型部署** | 大模型本地化/私有化部署（2卡/4卡环境），编写部署手册 |
| **Prompt 工程** | 多语种订单解析、图纸语义理解、标红说明生成；迭代优化并留存版本对比 |
| **解析算法** | DXF/PDF 图纸尺寸/公差/技术要求提取；俄文 OCR 调优 |
| **比对策略** | 规则 + LLM 混合路由；不确定项才调大模型 |
| **精度调优** | 金标回归、误报漏报分析、Prompt/规则联合优化 |
| **评测体系** | 建立准确率口径、搭建自动化评测流水线 |

### 3.2 后端工程师（智能体工程向）

| 职责模块 | 具体工作 |
| :--- | :--- |
| **审核流水线** | 解析→比对→标红→人工状态机 |
| **规则引擎** | 尺寸、公差、技术要求的确定性比对 |
| **工具链** | Tool Schema、函数调用、调用日志 |
| **可观测性** | Trace、回放、监控埋点 |
| **生产保障** | 队列、断点恢复、超时降级、权限审计 |

### 3.3 数据工程师

| 职责模块 | 具体工作 |
| :--- | :--- |
| **数据治理** | 历史订单/图纸脱敏清洗 |
| **术语库** | 俄文↔中文工艺词条、材质/标准号对照 |
| **金标标注** | 标注规范、质检、版本管理 |
| **评测集** | 正常/退货/边界用例维护 |

## 四、硬性技能要求

### 4.1 必备（Must Have）

| 类别 | 要求 |
| :--- | :--- |
| **编程** | Python 熟练；熟悉 FastAPI / Flask 等后端框架 |
| **大模型应用** | LLM API 或本地模型部署经验；Prompt 设计与调优 |
| **文档理解** | OCR、PDF 解析、版面分析；有 DXF/CAD 经验加分 |
| **工程化** | 函数调用 / Tool Use；JSON Schema；异步任务队列 |
| **数据** | 能建设金标集、定义评测指标、跑回归测试 |
| **沟通** | 能把技术方案翻译成业务语言，与 40–50 岁审核员协作设计 UI |

### 4.2 加分（Nice to Have）

| 类别 | 要求 |
| :--- | :--- |
| 制造业 / 外贸订单场景经验 | 理解图纸、公差、GOST/ISO 标准 |
| 俄语/NLP 多语种处理 | 术语库、机器翻译 post-edit |
| GPU 部署 | vLLM / Ollama / TensorRT-LLM 等推理框架 |
| 可观测 | Langfuse、OpenTelemetry、自建 Trace 系统 |
| 私有化安全 | 内网部署、脱敏、审计日志 |

### 4.3 不需要（红旗）

- 只会 ChatGPT 套壳，无工程落地经验  
- 追求多 Agent 框架炫技，说不清业务拆解  
- 无评测意识，「感觉对了就上线」  
- 主张全自动审图、取消人工终审（制造场景高风险）

## 六、能力定级标准

| 级别 | 画像 | 本项目适配 |
| :--- | :--- | :--- |
| **初级** | 会调 API、写 Prompt；说不清状态与评测 | 不适合独立负责 |
| **中级** | 能拆工作流、设计工具；有基本日志 | 可参与阶段一/二开发 |
| **高级** | 方案选型准、工程稳、有评测闭环 | 可担任模块负责人 |
| **资深** | 四维齐全：人机边界、可观测、降级、可迭代 | 算法/后端负责人 |

## 七、面试流程建议（60–90 分钟）

| 阶段 | 时长 | 内容 |
| :--- | :---: | :--- |
| 业务拆解 | 20 min | 给图纸审核场景，画架构与状态机 |
| 工程深挖 | 20 min | 追问 1–2 个 Tool 设计 + 失败恢复 |
| 评测与排障 | 15 min | 「上线效果不佳怎么查」 |
| 生产与人机 | 15 min | 峰值、成本、护栏、人工边界 |
| 综合定级 | 10 min | 对照四维打分 |

### 评分表（每维度 1–5 分）

| 维度 | 1 分 | 3 分 | 5 分 |
| :--- | :--- | :--- | :--- |
| 架构拆解 | 方案含糊 | 能拆步骤 | 选型克制+验收清晰 |
| 工具工程 | 无工具概念 | Schema 基本合理 | 幂等/权限/压缩齐全 |
| 评测观测 | 无评测 | 有指标无回放 | 金标+Trace+回归 |
| 生产落地 | 只谈模型 | 有基本降级 | 人机边界+护栏完善 |

**录用建议：**

- 中级：四维均 ≥3，无 1 分项  
- 高级：至少两个维度 ≥4  
- 资深：四个维度均 ≥4，且有制造业/文档智能落地案例

## 八、大模型在本项目的角色（面试常问）

**一句话：** 规则算得准，大模型读得懂、说得清；人不看全图，只看标红。

| 大模型做 | 大模型不做 |
| :--- | :--- |
| 俄文/英文工艺语义理解 | 10.0 vs 10.5 数值判定 |
| 非标排版、批注理解 | 公差带数学计算 |
| 标红项中文摘要 | 最终放行决策 |
| 灰色地带「待确认」+ 置信度 | 替代审核员拍板 |

## 十、一句话招聘文案

> 招聘智能体工程师，负责零部件图纸审核系统：将俄罗斯订单与工程图纸自动比对、标红差异，审核员只看标红做最终判断。要求能拆业务、设计工具链、建评测体系、保障生产稳定——不是做 Demo，是做能上线、退货率从 20% 降到 5% 的系统。
